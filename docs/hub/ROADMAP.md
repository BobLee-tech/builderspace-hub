## 第 1 期上线步骤（2026-10-14 已按此执行）

1. 核心团队先在线上注册好账号（闸门上线后，没有许可就注册不了）。
2. 对生产库执行 Hub 迁移：`POSTGRES_URL=<直连地址> NODE_ENV=production pnpm --filter @kan/hub migrate`，再用 `cli doctor` 确认。
3. 合并到 `main`，触发生产部署。
4. 确认生产环境**没有**设置 `NEXT_PUBLIC_DISABLE_SIGN_UP`。
5. 验证：不带链接直接调注册接口返回 400；`/signup` 是「仅限受邀」说明页；用命令行给一个测试邮箱发许可，能注册一次、第二次显示已使用。
6. 空库起步：第一位所有者注册后，执行 `cli setup-projects --owner <邮箱>` 按标准结构建好项目和看板（他成为各项目管理员），再给其他人发预设了这些项目的注册许可。顺序不能反：Kan 遇到没有任何项目的新用户会强制弹出「创建工作区」，而注册许可只能预设已经存在的项目。

## 已定的产品决定

- 项目 = Kan 的工作区，职能 = 看板，任务 = 卡片，阶段 = 列。
- 新成员只能凭一次性链接注册，链接由管理员私下发送；第一版只支持邮箱加密码。
- 后台权限用单一函数 `can(role, permission)` 判定；所有者才能任命后台成员；不能撤掉最后一个所有者。
- 普通成员默认能做的事（2026-10-14 定）：加入被邀请的项目、查看任务；在项目里新建看板和任务、填写内容。不能建模板、不能建项目。具体权限要能在后台改。
- 后台只有后台管理员能进；管理员可以直接添加账号、修改账号、重置密码（2026-10-14 定）。
- 没有权限的按钮和入口一律不显示，而不是灰掉；成员和访客在每个项目里能做什么，在后台「项目权限」页统一设置（2026-10-14 定）。
- 首页下半部分就是当前范围（全部或某个项目）的总版，可以直接在首页拖动、改日期、新建任务，取代原来的「按职能看」数字表格（2026-10-14 定）。
- 每个项目有一个「总版」，汇总开发、运营、营销三块看板的任务，按职能用三种柔和的颜色区分（颜色可在后台改）；在总版里移动、改时间、新建，都和小看板是同一张卡片（2026-10-14 定）。
- 项目切换放在首页，不放在侧栏左上角：除了各个项目，还有一个「全部」。「全部」里只出现自己有权限的项目的任务和信息，没有权限的项目整个不显示（2026-10-14 定）。
- 我们自己的页面先只有中文，文案集中在 `apps/web/src/hub/copy/zh.ts`，结构上留了加第二种语言的口子。
- 大看板的列按规范阶段名识别，对不上的进「其他」列；可以跨列拖动，列内按截止日期排序。
- 视觉：黑白金属，动效克制。动效用 Motion，动态 emoji 用 Fluent Emoji Animated，字体用 Geist、Noto Sans SC、得意黑，都是开源许可。
- 个人日程只有本人能看，不写操作日志（日志对后台管理员可见）；之后如果要做「团队空闲时间」，只共享有空 / 没空，不共享标题（2026-10-14 定）。
- 连接 GitHub 用 GitHub App（只读、只对安装的仓库有效），不用 OAuth App；统计范围是后台给项目配的仓库，只算这个人能看的项目；奖励先不做，只展示活动统计，事件数据照常保存，以后再定怎么算（2026-10-14 定）。
