# 路线图

把原样的 Kan 改造成 BuilderSpace 的内部工具，分七期。每期是一到三个可以独立评审和上线的 PR。

| 期  | 内容                                                                                                                                                 | 状态             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 1   | **准入闸门**：`packages/hub` 底座、独立迁移、操作日志、注册许可、一次性注册链接、命令行、登录页和「仅限受邀」页、接缝检查                            | 代码完成，待上线 |
| 2   | **账号、权限、接口底座**：后台角色（所有者 / 管理员 / 只读）和 `can()`、停用账号、`hub.*` 接口、只有后台管理员能建项目、没有项目的人看到「等待分配」 | 未开始           |
| 3   | **设计底座 + 后台第一版**：配色字体、基础组件；后台的注册许可、成员、后台成员、操作日志                                                              | 未开始           |
| 4   | **申请表与职位**：公开的申请表和审批；谁负责哪个项目的哪个职能                                                                                       | 未开始           |
| 5   | **新导航、首页、大看板**：上下两排分类加「我负责的」；跨项目按阶段分列的大看板                                                                       | 未开始           |
| 6   | **全站中文与动效**：`zh` 语言包并设为默认；动态 emoji、数字滚动、列表过渡                                                                            | 未开始           |
| 7   | **收尾**：后台的项目与职能管理；配置发信前修掉 Kan 邀请接受逻辑的越权；把 `packages/builderspace` 并入 `packages/hub`                                | 未开始           |

## 第 1 期上线步骤

1. 核心团队先在线上注册好账号（闸门上线后，没有许可就注册不了）。
2. 对生产库执行 Hub 迁移：`POSTGRES_URL=<直连地址> NODE_ENV=production pnpm --filter @kan/hub migrate`，再用 `cli doctor` 确认。
3. 合并到 `main`，触发生产部署。
4. 确认生产环境**没有**设置 `NEXT_PUBLIC_DISABLE_SIGN_UP`。
5. 验证：不带链接直接调注册接口返回 400；`/signup` 是「仅限受邀」说明页；用命令行给一个测试邮箱发许可，能注册一次、第二次显示已使用。

## 已定的产品决定

- 项目 = Kan 的工作区，职能 = 看板，任务 = 卡片，阶段 = 列。
- 新成员只能凭一次性链接注册，链接由管理员私下发送；第一版只支持邮箱加密码。
- 后台权限用单一函数 `can(role, permission)` 判定；所有者才能任命后台成员；不能撤掉最后一个所有者。
- 我们自己的页面先只有中文，文案集中在 `apps/web/src/hub/copy/zh.ts`，结构上留了加第二种语言的口子。
- 大看板的列按规范阶段名识别，对不上的进「其他」列；可以跨列拖动，列内按截止日期排序。
- 视觉：黑白金属，动效克制。动效用 Motion，动态 emoji 用 Fluent Emoji Animated，字体用 Geist、Noto Sans SC、得意黑，都是开源许可。
